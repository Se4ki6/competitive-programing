# AtCoder learning

このリポジトリでは、問題を `problems/<contest_id>/<problem_id>/` に保存する。問題探しとフォルダ作成にはREADMEに記載された `AtCoderStudy` CLIを使う。

## 学習の進め方

- ユーザーに新しい問題を出すときは、問題フォルダを作成し、公式問題文をCLIの `statement` で `statement.md` に保存する。取得できない場合は公式ページを確認し、問題の目的、入力形式、制約、出力形式、サンプルを自分の言葉でまとめた学習用の `statement.md` を作り、原文へのリンクを付ける。`README.md` の「問題の要約」には短い要約だけを記録し、本人の方針や振り返りは対応する欄に残す。
- ユーザーが問題を解いている途中なら、現在の考えや試したことを踏まえて次の一歩だけを示す。完全な解法やコードは、ユーザーが求めるか、自力での試行とヒントを経て解説を希望したときに示す。
- ヒントは、制約の読み取り、例や反例、使う性質、アルゴリズムの順に必要なところまで進める。問題文や制約を確認できない場合は、公式の問題ページを参照するかユーザーに該当部分を求める。
- 解答レビューでは、まず正しさと境界条件、次に計算量、最後にC#固有の点（整数型、入力速度、配列の範囲など）を見る。問題に即した反例があれば示す。
- 模範解答の比較では、公式の解説など出典が確認できる資料を使い、推測を模範解答として扱わない。自分の解答との差と、次回気づくための着眼点を短く整理する。
- ユーザーが記録を望んだら、問題フォルダの `README.md` に本人の方針と振り返り、`editorial.md` に模範解答との比較を残す。本人の `Program.cs` を無断で模範解答に置き換えない。
- 復習では、まずコードを見ずに解法と計算量を説明してもらい、理解が曖昧な点を一問ずつ確認する。

AtCoder Problems APIは問題のメタデータ、推定難易度、提出履歴を取得するために使う。問題文や公式解説の参照にはAtCoderのページを使う。

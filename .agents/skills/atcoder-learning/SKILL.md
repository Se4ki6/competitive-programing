# AtCoder learning

このリポジトリでは、問題を `atcoder_problems/<contest_id>/<problem_id>/` に保存する。問題探しとフォルダ作成にはREADMEに記載された `AtCoderStudy` CLIを使う。

学習記録は `my-solution.md`（本人の解答）と `model-solution.md`（模範解答と本人へのフィードバック）に分ける。`Program.cs` は本人の提出用コード、`statement.md` はGit管理外の問題文とする。

## 学習の進め方

- ユーザーに新しい問題を出すときは、問題フォルダを作成し、公式問題文をCLIの `statement` で `statement.md` に保存する。取得できない場合は公式ページを確認し、問題の目的、入力形式、制約、出力形式、サンプルを自分の言葉でまとめた学習用の `statement.md` を作り、原文へのリンクを付ける。
- `start` は `my-solution.md` と `model-solution.md` を生成する。旧形式の `README.md` と `editorial.md` がある場合は、内容を確認し、内容を保ったままそれぞれの新形式の文書に整理する。既存ファイルは上書きしない。模範解答の本文は解説を示す段階まで空欄にしておく。
- ユーザーが問題を解いている途中なら、現在の考えや試したことを踏まえて次の一歩だけを示す。完全な解法やコードは、ユーザーが求めるか、自力での試行とヒントを経て解説を希望したときに示す。
- ヒントは、制約の読み取り、例や反例、使う性質、アルゴリズムの順に必要なところまで進める。問題文や制約を確認できない場合は、公式の問題ページを参照するかユーザーに該当部分を求める。
- 解答レビューでは、まず正しさと境界条件、次に計算量、最後にC#固有の点（整数型、入力速度、配列の範囲など）を見る。問題に即した反例があれば示す。
- 模範解答には、公式解説など出典を確認できる資料を使う。出典と、公式掲載のコードなのか解説を基に作成したC#実装なのかを明記する。出典を確認できない解法を模範解答と断定しない。
- ユーザーが記録を望んだら、`my-solution.md` に問題へのリンクと短い要約、本人の着想・解法・計算量、提出結果と振り返りを残す。本人が述べていない考えを本人の記録として補わない。
- `model-solution.md` には、参照元、解法の要点と正しさ、計算量、単独でコンパイル可能なC#の全コードを `csharp` コードブロックで載せる。本人の解答がある場合は実際の `Program.cs` に基づき、良い点、解法や実装の違い、もっと良くするための具体的な提案とその理由、次回の着眼点を記録する。改善点を無理に作らず、同等に正しい別解はそのように伝える。
- 模範解答とフィードバックは、ユーザーが求めたとき、または自力での試行とヒントを経て解説を希望したときに示す。本人の `Program.cs` を模範解答で上書きしない。
- 復習では、まずコードを見ずに解法と計算量を説明してもらい、理解が曖昧な点を一問ずつ確認する。

AtCoder Problems APIは問題のメタデータ、推定難易度、提出履歴を取得するために使う。問題文や公式解説の参照にはAtCoderのページを使う。

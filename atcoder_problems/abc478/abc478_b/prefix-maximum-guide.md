# ABC 478 B：O(N²) の別解を一歩ずつ理解する

[問題文](https://atcoder.jp/contests/abc478/tasks/abc478_b)｜[模範解答と比較](model-solution.md)

この文書では、先に 2 種類を決め、残り 1 種類をすばやく選ぶ方法を説明します。初めて読むときは、コードより先に具体例を追ってみてください。

この問題は 3 重ループでも十分間に合います。ここでの方法は、さらに計算回数を減らすための練習です。

## 1. まず問題を確認

入力例 1 を使います。

```text
N = 5, V = 9
嬉しさ = 31 41 59 26 53
```

| トッピングの番号 | 1 | 2 | 3 | 4 | 5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 価格 | 1 | 2 | 3 | 4 | 5 |
| 嬉しさ | 31 | 41 | 59 | 26 | 53 |

番号がそのまま価格です。例えば 3 番を選ぶと、価格は 3、嬉しさは 59 です。異なる 3 種類を選び、価格の合計を 9 以下にします。

選ぶ 3 つの番号を小さい順に `i`, `j`, `k` と呼びます。例えば 1 番・3 番・5 番なら `i = 1`, `j = 3`, `k = 5` です。このように並べると必ず `i < j < k` になります。

## 2. 何を速くしたいのか

3 重ループでは、`i`, `j`, `k` の候補をすべて試します。別解では、まず `j` と `k` の 2 つを決めます。

このとき、**`j` と `k` の嬉しさはもう決まっています**。残りの予算で選べる `i` のうち、嬉しさが最大のものを選べば、その `j`, `k` に対する最良の合計が分かります。

ただし `i` にもループを使うと、`j`, `k` を選ぶたびに、`i` の候補を繰り返し調べることになります。そこで、後で何度も使う「1 番からある番号までの嬉しさの最大値」を、前もって調べて保存します。

## 3. `best[x]` は何を保存する？

`best[x]` は **1 番から x 番までの嬉しさの最大値**です。トッピングの番号ではなく、嬉しさの値を保存します。

| x | 調べる範囲の嬉しさ | `best[x]` |
| ---: | --- | ---: |
| 1 | 31 | 31 |
| 2 | 31, 41 | 41 |
| 3 | 31, 41, 59 | 59 |
| 4 | 31, 41, 59, 26 | 59 |
| 5 | 31, 41, 59, 26, 53 | 59 |

例えば「1〜4 番の中で一番嬉しいもの」は `best[4]` を見るだけで 59 と分かります。**4 番の嬉しさ 26 ではありません**。1〜4 番の中の最大値です。

### `best` を作るときも全探索しているのでは？

はい。`best` を作るときは、1 番から N 番までの嬉しさを **1 回ずつ**調べます。その際、各位置までの最大値を記録します。

ただし、この段階では **3 種類の組み合わせや予算を調べていません**。例えば、入力例では `best[3] = 59` と分かりますが、それだけでは 3 番と一緒にどの 2 種類を選べるのか、予算内で嬉しさの合計が最大になるのはいくつかは分かりません。

`best` を作った後、`j`, `k` を選ぶ 2 重ループで、3 種類の組み合わせを考えます。そのとき必要になる `i` の最大の嬉しさを、`best` を見てすぐ取り出します。

| いつ | 調べること | 結果 |
| --- | --- | --- |
| 最初に 1 回 | 各番号までの嬉しさの最大値 | `best[1]`, `best[2]`, … を保存 |
| `j`, `k` ごと | 予算と番号の条件で、`i` が何番まで選べるか | 上限 `limit` を求め、`best[limit]` を使う |

例えば予算 9 なら、`j = 3`, `k = 4` のとき `i` は 2 番までなので `best[2]` を使います。`j = 3`, `k = 5` のときは残り予算が 1 なので `best[1]` を使います。候補の範囲が変わっても、それぞれの最大値を最初に保存してあるため、1 番から調べ直す必要がありません。

つまり、**`best` は 2 重ループをなくすものではなく、2 重ループの中で `i` を探す作業を省くためのもの**です。

### どうやって作る？

1〜3 番の嬉しさは `31, 41, 59` なので、その最大値は `best[3] = 59` です。次に、4 番の嬉しさ `26` も含めた最大値を知りたいとします。

1〜3 番の中では 59 が一番大きいことが分かっているので、あとは **59 と 26 のどちらが大きいか**を比べるだけです。数値を足すわけではありません。

```text
best[4] = 59 と 26 の大きい方 = 59
```

もし 4 番の嬉しさが 70 だったら、59 より大きいので `best[4] = 70` になります。同じ比較を 1 番から順に行います。

```csharp
int[] best = new int[n + 1];
for (int x = 1; x <= n; x++)
{
    best[x] = Math.Max(best[x - 1], w[x - 1]);
}
```

`Math.Max(a, b)` は大きい方を返します。`best[0]` の初期値は 0 です。この問題の嬉しさはすべて 1 以上なので、最初の比較にも使えます。

トッピングの番号は 1 から、入力配列 `w` の添字は 0 からです。つまり **x 番の嬉しさは `w[x - 1]`** です。一方、`best` は番号に合わせて `best[1]` から使うため、長さを `n + 1` にしています。

## 4. まず `j = 3`, `k = 4` に決める

| 選んだ番号 | 価格 | 嬉しさ |
| --- | ---: | ---: |
| j = 3 | 3 | 59 |
| k = 4 | 4 | 26 |

予算は 9 なので、残りは `9 - 3 - 4 = 2` です。残り 1 種類 `i` には、2 つの条件があります。

1. **予算の条件**：価格は残りの 2 以下。番号が価格なので `i <= 2`。
2. **番号の条件**：`i < j`。`j = 3` なので `i <= 2`。

どちらも満たす `i` は 1 番か 2 番です。嬉しさはそれぞれ 31 と 41 なので、2 番を選ぶのが最良です。

ここで `best[2]` を見ると、1〜2 番の嬉しさの最大値 41 がすぐに分かります。よって、この `j`, `k` に対する最良の合計は次のとおりです。

```text
best[2] + 3番の嬉しさ + 4番の嬉しさ
= 41 + 59 + 26
= 126
```

## 5. `limit` はどう決める？

`limit` は、残りの番号 `i` として選べる最大の番号です。2 つの条件を両方満たす必要があります。

- `i < j` なので、`i` は **`j - 1` 以下**。
- `i + j + k <= v` なので、`i` は **`v - j - k` 以下**。

両方を満たすため、小さい方を上限にします。

```csharp
int limit = Math.Min(j - 1, v - j - k);
```

`Math.Min(a, b)` は小さい方を返します。

### 2 つの上限を使う理由

例えば、予算が仮に 12 で `j = 3`, `k = 4` の場合、残りの予算は 5 です。しかし `i < 3` なので、`i` に 3〜5 番は使えません。上限は `min(2, 5) = 2` です。

逆に予算 9、`j = 3`, `k = 5` の場合は、`i < 3` なら 2 番までですが、残りの予算は 1 です。上限は `min(2, 1) = 1` です。

**予算の条件と番号の条件は別々に必要**です。

### `limit` が 0 以下のとき

例えば予算 9、`j = 4`, `k = 5` の場合、残りの予算は 0 です。トッピングの価格は最低でも 1 なので、`i` は選べません。この組み合わせは飛ばします。

```csharp
if (limit >= 1)
{
    // 選べる i がある場合だけ計算
}
```

## 6. `j`, `k` の組み合わせをすべて調べる

入力例 1 では、`j < k` を満たす候補のうち `j >= 2` のものを次のように調べます。`j = 1` では、それより小さい `i` が存在しません。

| j | k | limit | 最良の i の嬉しさ | 嬉しさの合計 | answer |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 2 | 3 | 1 | `best[1] = 31` | 31 + 41 + 59 = 131 | 131 |
| 2 | 4 | 1 | `best[1] = 31` | 31 + 41 + 26 = 98 | 131 |
| 2 | 5 | 1 | `best[1] = 31` | 31 + 41 + 53 = 125 | 131 |
| 3 | 4 | 2 | `best[2] = 41` | 41 + 59 + 26 = 126 | 131 |
| 3 | 5 | 1 | `best[1] = 31` | 31 + 59 + 53 = 143 | 143 |
| 4 | 5 | 0 | 選べない | 計算しない | 143 |

`answer` はループの外で 0 に初期化し、各組み合わせを調べるたびに、それまでの最大値と新しい合計を比較します。最後の答えは **143** です。

## 7. コード全体

以下は[模範解答](model-solution.md)にある別解と同じ動きです。コメントを増やしています。

```csharp
using System;

internal static class Program
{
    private static void Main()
    {
        string[] first = Console.ReadLine()!.Split();
        int n = int.Parse(first[0]);
        int v = int.Parse(first[1]);
        int[] w = Array.ConvertAll(Console.ReadLine()!.Split(), int.Parse);

        // best[x] = 1 番から x 番までの嬉しさの最大値
        int[] best = new int[n + 1];
        for (int x = 1; x <= n; x++)
        {
            best[x] = Math.Max(best[x - 1], w[x - 1]);
        }

        // 全組み合わせに共通する最大値。ループの外で初期化する。
        int answer = 0;
        for (int j = 2; j <= n; j++)
        {
            for (int k = j + 1; k <= n; k++)
            {
                // i < j と価格の合計 <= v の両方を満たす上限
                int limit = Math.Min(j - 1, v - j - k);
                if (limit >= 1)
                {
                    // 選べる i の最大の嬉しさと、j、k の嬉しさを足す。
                    int happiness = best[limit] + w[j - 1] + w[k - 1];
                    answer = Math.Max(answer, happiness);
                }
            }
        }

        Console.WriteLine(answer);
    }
}
```

## 8. なぜ答えが漏れない？

どの 3 種類も番号順に並べると、必ず 1 通りの `i < j < k` になります。2 重ループは、その `j`, `k` の組み合わせを調べます。

そのとき、条件を満たす `i` は 1 番から `limit` 番までです。`best[limit]` はその範囲の最大の嬉しさなので、その `j`, `k` について、どの `i` を選ぶよりも嬉しさの合計が小さくなることはありません。これを全 `j`, `k` で比べるので、最終的な最大値が答えです。

## 9. 計算量と出典

`best` の作成は N 回の処理なので O(N)。`j`, `k` の 2 重ループは O(N²) で、各組み合わせの計算は定数時間です。全体では **時間 O(N²)、空間 O(N)** です。
